# 事件墙 服务端

部署方法见 `deploy/install.sh` 开头的说明。

## 用 Telegram 审核

开启后，每条新投稿和待审核的评论都会由机器人发到审核群（或和你的私聊）里。点按钮就能审核：

- 投稿：**✅ 通过** 或 **❌ 拒绝…**。拒绝时可以选一个常用原因，也可以点「自己写原因」，然后回复机器人的那条消息。
- 评论：**✅ 通过** 或 **❌ 拒绝**。
- `/pending`：把所有待审核的内容重新发一遍。
- `/id`：在和机器人的私聊里发这个命令，机器人会告诉你自己的 Telegram 用户 ID。

审核结果和网页后台是同一套逻辑：操作日志里的管理员记为 `tg:<名字>`，GitHub 导出也会照常进行。在网页后台审核，或者作者自己撤回，Telegram 里的对应消息也会跟着更新。

### 隐私

- 发到 Telegram 的只有投稿人自己写的内容。服务端本来就没有 IP、设备或账号信息，所以也不会发出去。图片用的是服务器重新编码后的副本，已经去掉 EXIF、GPS 和相机信息。
- 所有消息都设置了 `protect_content`：不能转发、复制或保存。图片默认加遮罩，点开才能看。
- 审核一结束（通过、拒绝、删除或作者撤回），机器人就删掉图片，并把文字改成一行状态。已通过的投稿只保留标题和公开链接。发出超过 48 小时、Telegram 不再允许删除的图片，会被换成一张灰色图片。
- 机器人只在 `TG_CHAT_ID` 这一个聊天里工作，只有 `TG_ADMINS` 里列出的人能操作。其他人点按钮只会看到「没有审核权限」。
- 机器人用长轮询（getUpdates）接收消息，不需要对外开放任何地址。日志里不会出现 token 和聊天 ID。
- 审核群里的其他成员都能看到待审核的内容，所以只拉信得过的审核员进群，也可以直接用私聊。

### 配置步骤

1. 在 @BotFather 创建机器人，把 token 存进 Parameter Store：`/end-gfw/board/TG_BOT_TOKEN`（SecureString）。
2. 在 `/etc/end-gfw-board/settings` 里加上：
   ```
   TG_CHAT_ID=<私聊填你的用户 ID；群聊填群 ID，以 -100 开头>
   TG_ADMINS=<名字>:<Telegram 用户 ID>,<名字>:<Telegram 用户 ID>
   ```
   如果是私聊，`TG_ADMINS` 可以不填，聊天的那个人就是审核员。
3. 重新运行 `deploy/install.sh`。启动日志里出现 `telegram: true`，就说明已经开启。

token、群 ID 和用户 ID 都不要写进仓库。
